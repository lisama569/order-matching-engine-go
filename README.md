# order-matching-engine-go

可确定性重放的限价订单簿撮合与执行服务（纯内存，无外部依赖）。

- 限价单 / 市价单（市价为 IOC，残余撤销），价格优先、时间优先；
- 部分成交、撤单；非法数量、价格越界、不可接受委托给出**可区分**拒绝原因；
- 全部状态变更记录为严格连续有序事件，可从事件流断点重建；
  序号重复 / 乱序 / 缺口明确拒绝，不静默跳过；
- 撮合结果向多订阅者非阻塞分发，慢订阅者被断开而不阻塞撮合、不丢事件（可重连追赶）；
- 账户净持仓、挂单笔数、名义敞口、单笔金额风控；触发限额即拒绝且状态不变；
- **盘口快照**：随时查询买卖各档价位 / 剩余总量 / 挂单笔数，与挂单明细严格一致；
  取快照走原子发布，不阻塞撮合、不丢事件，并发下也是完整一致的视图；
- **账实一致性审计**：盘口汇总、账户敞口与名义占用、事件进度三方互相对账；
  任何不一致都判定不通过，并给出类别与差异大致所在的事件序号；
- **检查点与增量重建**：事件流推进中可落检查点（带校验和、可落盘），
  之后基于检查点续放增量事件即可补齐状态，与从零全量重建逐字段一致；
  缺失 / 损坏 / 放错位置的检查点被识别并安全退回全量重建；
- 一把锁串行化状态变更，并发下单 / 撤单结论确定，`-race` 干净。

详细设计见 [docs/design.md](docs/design.md)。

## 本地验证

```bash
go build ./...
go test ./... -v          # 日志含事件序号与判定依据
go test -race ./...       # 并发安全
go run ./cmd/matchingd    # 固定脚本演示：撮合 + 重建 + 快照/审计/检查点
go test -bench=Rebuild -benchmem ./internal/engine/   # 全量 vs 检查点增量重建性能
```

## 兼容性

老的事件流不做任何迁移即可继续全量重放（`Replay` 行为不变；
`Rebuild(nil, events)` 等价于全量重放）。检查点为可选能力：
不启用时系统行为与上一版完全一致。
